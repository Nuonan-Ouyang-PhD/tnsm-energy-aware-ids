\begin{abstract}
Runtime model selection is an attractive way to trade detection quality against energy and latency at the edge, yet published evaluations often compare a learned selector only against a more expensive static detector, conflating detector choice with adaptive value. We develop a framework and physical measurement study that separates these two effects. First, we derive a \emph{pairwise non-degeneracy criterion} that, given the declared reward, cost profile, and support region, decides before deployment whether any state can flip a preferred action; the criterion turns reward normalization from an unaudited hyperparameter into a pre-deployment screening test. Second, we specify an evaluation protocol built on trace-matched paired blocks, prospectively frozen factorial workloads, separated raw and drift-adjusted endpoints, and explicit off-support behavior reporting. Third, we execute the protocol on a Raspberry Pi 4B with four frozen TON-IoT detectors, tabular Q-learning, DQN, a fixed confidence cascade, and a causal DeadlineGuard rule. Under a $50/100/4000\text{ rows/s}\times 0.10/0.50/0.90$ prevalence factorial, DeadlineGuard cuts energy by 43.7~J per run against Static-MedRF (2.98\%; 95\% paired CI 41.4--46.0~J) and eliminates all 512/5,000 deadline misses at a 1.373-pp F1 cost, whereas both learned selectors realize a static schedule that the non-degeneracy criterion correctly predicts. When the workload shifts off the training support, Q-learning's deterministic tie rule promotes a TinyDT default with 67.76\% FPR, exposing a transferable safety risk in sparse discrete controllers. The framework and evidence together indicate when learned model selection adds adaptive value and when a simple causal rule or an audited static choice is preferable in edge intrusion detection service management.
\end{abstract}
