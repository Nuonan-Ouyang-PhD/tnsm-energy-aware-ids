## E01：批准的 ZIP 未绑定实际传入的合同/运行工作副本

### 定位

`scripts/materialize_dataset_native_v1.py` 的 `validate_authorization`（L287–L335）验证授权记录中的 evidence ZIP 哈希，却未比较运行时 `--contract` 与该 ZIP 对应成员的字节；运行脚本与包内批准源码也没有绑定。`main` 随后从传入路径再次加载合同执行。

### 独立复现

使用真实 ZIP 格式打包一套人工合成 fixture，并创建只用于该测试的授权记录。原合同正常运行；归档和授权固定后，只修改工作副本合同，将 TON 的排除字段 `src_ip` 改成 `proto`（输出特征数仍为2），不修改已绑定 ZIP 或授权记录。

实际 CLI 仍退出0并发布合成输出；特征表头从 `proto,duration` 变成 `src_ip,duration`，源 IP 出现在输出。运行脚本本身保持原样。

这不是声称“没有授权也能运行”，也不是声称篡改会保持原 ZIP 哈希；复现的是已绑定的归档仍完好，但执行器没有拒绝归档之外的本地合同漂移。

### 必须达到的修复行为

在任何源数据目录检查、源 CSV 打开或 staging 创建之前，将外部授权绑定的证据 ZIP 与实际合同、实际执行源码及全部必需依赖建立字节级绑定。安全解析归档/清单或使用绑定到已批准 ZIP 的执行清单均可；不能只比较 contract_id 字符串。未审合同变更、运行源码变更或证据依赖变更必须拒绝。保留冻结输入哈希守护。

证据：`synthetic_contract_binding_cli.log` 与 `boundary_probe_results.json` E01。

## E02：重放文件绕开字节预算和空间保留检查

### 定位

`_execute_authorized` L806–822 为整套数据集建立 `.replay-*` 目录，每个 replay render 传入 `budget=None`，且直到整个数据集结束才删除这些副本。空间检查在正常分片写出后执行，重放内部不执行。

### 独立复现

给人工 CIC fixture 添加两个合法的50,000字符文本字段；先测得完整合成输出112,191 B。随后将输出硬上限设为112,191 B、保留空间设为1,024 B，并给执行器传入“总可用113,215 B减去当前 staging 已写字节”的受控可用空间函数。

重放期间实际合成 staging 峰值202,532 B，模型中的空间已为0；执行器未在该阶段调用空间检查，重放清理后仍发布最终输出。最多同时保留8个重放文件。最终输出本身确实未超过112,191 B；缺失的是临时重放占用的预算/检查。

这没有填满真实磁盘，也不证明真实 ENOSPC 时仍会成功发布；它证明已声明的 scratch 保留没有覆盖该写入阶段。真实执行可能落到操作系统写失败，而不是合同承诺的提前预算保护。

### 必须达到的修复行为

优先将重放改为流式 CSV 序列化哈希校验，不生成完整副本。若必须落盘，需为重放配置独立但受总空间约束的预算、逐分片释放并在写入阶段检查剩余空间，预算须覆盖峰值同时占用。不能仅增大新盘而保留无界重放。

证据：`synthetic_replay_space_trace.json`、`boundary_probe_results.json` E02。

## E03：输入预检遗漏了一个冻结输入，且尾行规则与冻结例外冲突

### E03a：零行结构文件跳过了身份检查

`data_source_items` 在排除 `demonstrate_structure.csv` 后被预检复用；`validate_source_set` 仅确认该文件名存在。结果预检只逐字节验证399个数据文件，未验证冻结清单中的零行结构文件。

在合成 fixture 中只给该结构文件附加一条数据行，不更新 inventory 或任何绑定，执行仍成功。不能仅因不产生分片，就不验证它仍是被冻结的零行文件。

修复要求：全部400项都验证源身份/字节/表头/行数；结构文件确认为既定零行后，只从渲染、排序编号和分片集合排除。若内容发生变化应拒绝，不得静默放过或变成新排除项。

### E03b：终端LF规则

冻结的三条 CIC exception 均明确 `ends_with_newline=false`，但合同写成所有源行（包括最终行）必须带 LF。现有三个人工异常样例全部带 LF，没有覆盖真实登记例外的这个形态。

解析器实际也没有执行这个全局要求。在独立合成测试中，去掉一条正常TON末行LF，重新绑定合成inventory后仍发布；同样，精确注册为无LF的三个人工CIC尾行仍可以排除。实现当前没有把两种情形区别处理。

修复要求：合同明确“既定、逐哈希匹配的三条无LF截断尾行为精确例外；不是泛化容忍或新增行排除”。将带/不带LF的普通末行、注册/未注册的截断末行分别测试，保留预定三行排除集，原数据不修改。

证据：`supplementary_review.json` 的冻结exception字段；`boundary_probe_results.json` 三个E03场景。

## E04：发布和清理在目录被并发创建/替换时不满足边界

### 独立复现

1. 首次路径检查通过后，在最终元数据复核阶段由测试钩子创建一个空的最终输出目录。最后 `os.replace` 将其替换，返回成功。仅启动时检查 exists 不能实现发布时的no-clobber。
2. 执行器创建staging后，测试钩子将其移走，在同一位置创建属于模拟第二进程的目录及sentinel，然后抛出异常。清理只用路径形式和布尔值判断，删除了替代目录及sentinel。

这是隔离临时目录中的有意竞态注入。正常单进程路径的包内测试通过，不代表这两个边界通过；未在用户机器执行覆盖、删除或正式发布。

### 必须达到的修复行为

发布需要在最终原子操作中拒绝已有目标，不依赖早先exists检查。清理必须绑定本次创建的目录身份/所有权，并防止验证到删除之间被替换；陌生目录保留并报告。新盘路径rebind时验证目标文件系统的对应发布行为，不能仅称“atomic”就等同“no overwrite”。

证据：`boundary_probe_results.json` 两个E04场景。

## 重现工具

`probe_executor_boundaries.py` 只使用源包内明确的人工 fixtures 和独立临时目录；不运行任何真实数据任务。

```sh
PYTHONDONTWRITEBYTECODE=1 python3 probe_executor_boundaries.py \
  --package-root /path/to/materialization_executor_evidence_v1 \
  --report-dir /path/to/separate/review-output
```

工具输出的是观察结果，当前失败情景预期会在修复版本中由“允许/发布”变成“拒绝”。脚本不是修复后的执行器，也不签发任何操作授权。
