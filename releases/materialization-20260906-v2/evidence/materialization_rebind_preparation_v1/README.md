## 新卷到位后的实际流程

1. 记录挂载点、物理设备及卷标识、卷名、容量、当前可用字节、文件系统、只读标志和可写状态。通过设备及物理存储关系确认实际外接盘；不只凭卷名或容量挑选。
2. 选定卷上的现有父目录，将拟议 output 和 staging 记为绝对路径的同级子目录，staging 名为 `.<output名称>.staging`。两者必须不存在，父目录设备身份相同。此时只验证路径，不创建正式目录。若需专用父目录，记录为待建路径，并在授权中明确。
3. 在该卷创建唯一、独立的非数据临时目录，仅使用小型人工哨兵。调用基线中未改动的 `create_staging_lease` 和 `atomic_publish_noreplace`，不调用 materializer 主入口，不构造真实执行授权。
4. 逐项记录：目标不存在时成功发布且 inode/内容保持；晚到的空目录、非空目录、普通文件、符号链接分别被拒绝，原目标身份及内容保持；失败 staging 被保留。记录调用错误与设备/目录身份。不支持原生 `RENAME_EXCL` 时保留证据并阻止重绑定通过，不切换覆盖式发布。
5. 能力探测包含少量人工文件写入，不能标作全程只读。记录临时路径和实际占用；保留失败目录和外来对象，不自动递归清理。
6. 汇总实际空间与路径、原生探测日志、基线/复验包哈希及运行文件绑定。输出硬上限维持 25,671,749,556 B，最低可用空间维持 26,745,491,380 B；两者都是合同门槛，不是新盘实测值。正式运行前仍须重新检查空间。
7. 另建重绑定候选工件，保存 V1R2 原包不变。重绑定后的合同字节将不同，必须重新生成其合同、MANIFEST 和候选 ZIP 哈希，授权不得继续拿 V1R2 原包哈希绑定新合同。审核差异应仅限获准的路径、卷与空间绑定等部署元数据；两个冻结 config、原生 32/39/115 特征、标签和三条既定例外保持原值。
8. 实际新卷验证通过并完成具体 rebind 包后，再提交 materialization 单项执行申请，并在后续明确授权记录中绑定最终工件。splitting 和 training 不并入申请。
